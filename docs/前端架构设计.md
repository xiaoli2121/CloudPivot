# CloudPivot 前端架构设计

## 1. 设计目标

CloudPivot 前端架构需要同时支撑平台管理、低代码设计态和运行态应用三类场景，设计目标如下：

- 支持多应用协同与共享能力复用
- 支持统一认证、菜单、路由和权限控制
- 支持低代码设计器与运行容器共用核心模型
- 支持插件扩展与行业化二次开发

## 2. 工程结构

前端工程采用工作区模式，根工程为 `cloudpivot-vue3`。

### 2.1 应用层

- `apps/admin-shell`：管理后台主入口
- `apps/designer-studio`：低代码设计器
- `apps/runtime-app`：低代码运行容器
- `apps/portal-app`：门户预留应用

### 2.2 共享包层

- `packages/core`：应用启动、全局注册、基础能力整合
- `packages/ui`：平台级通用 UI 组件
- `packages/sdk`：统一接口调用、鉴权封装、数据对象转换
- `packages/shared-types`：共享类型定义
- `packages/shared-utils`：工具函数与通用方法
- `packages/designer-core`：设计器核心模型与服务
- `packages/designer-components`：设计器可视化组件物料
- `packages/runtime-engine`：运行态元数据解析与页面渲染核心

## 3. 应用职责划分

### 3.1 Admin Shell

负责：

- 登录与首页
- 菜单导航与工作台
- 系统管理、组织权限、参数配置等平台功能
- 插件应用入口汇聚

### 3.2 Designer Studio

负责：

- 页面设计
- 表单设计
- 组件属性配置
- 发布与草稿管理

### 3.3 Runtime App

负责：

- 解析元数据
- 动态渲染页面与表单
- 处理运行态事件、校验与数据交互

## 4. 前端分层

### 4.1 表现层

- 页面视图
- 基础布局
- 通用组件
- 图表与交互控件

### 4.2 应用层

- 路由编排
- 菜单装配
- 权限守卫
- 应用初始化

### 4.3 领域支撑层

- 认证状态管理
- 用户上下文
- 元数据模型管理
- 页面配置与设计态状态管理

### 4.4 基础设施层

- HTTP 请求封装
- 本地缓存封装
- 错误处理
- 日志与埋点预留

## 5. 路由与菜单设计

### 5.1 路由设计

路由分为：

- 静态路由：登录页、错误页、基础布局页
- 动态路由：根据后端菜单和权限动态装配
- 插件路由：插件在扩展点中注册的路由

### 5.2 菜单设计

- 后端返回菜单树
- 前端根据权限与路由映射关系生成导航结构
- 按钮权限与页面资源点在组件层做显隐控制

## 6. 状态管理设计

核心状态域包括：

- 用户与登录态
- 菜单与权限
- 系统配置与字典缓存
- 设计器工作状态
- 运行态页面上下文

状态管理策略：

- 全局共享状态进入 Pinia
- 页面临时状态保留在局部组件或组合式函数中
- 避免所有状态都堆入全局仓库

## 7. 接口通信设计

- 所有接口请求统一由 `packages/sdk` 封装
- 统一处理令牌、错误码、重复登录、无权限提示
- 统一处理分页请求和标准响应结构
- 统一兼容后端文件上传、导出与下载

## 8. 权限与安全设计

前端安全侧重点包括：

- 登录后加载用户信息、角色和菜单
- 路由守卫校验是否登录
- 基于权限码控制按钮和组件显示
- 敏感数据不在前端做最终可信判断

原则：

- 前端只做体验控制
- 后端负责最终安全校验

## 9. 低代码前端支撑设计

### 9.1 设计器核心

- 组件物料注册
- 属性面板配置
- 画布编排
- 事件与动作配置

### 9.2 运行引擎核心

- 元数据解析器
- 页面布局渲染器
- 表单引擎
- 动作执行器

### 9.3 模型统一

设计态和运行态共享统一元数据结构，避免“双模型”导致设计发布不一致。

## 10. 插件扩展设计

前端需要为以下扩展点提供基础能力：

- 菜单扩展
- 路由扩展
- 页面组件扩展
- 设计器物料扩展
- 工作台卡片扩展

扩展方式：

- 注册式装配
- 动态加载或按需打包
- 扩展点统一声明和校验

## 11. 社区版 1.0 落地重点

- 完成 Admin Shell 的基础管理能力骨架
- 完成登录、菜单、权限守卫和标准 API 通信
- 完成 Designer Studio 与 Runtime App 的最小可运行骨架
- 沉淀共享包边界，为后续功能扩展提供稳定基线

## 12. 设计结论

CloudPivot 前端架构采用多应用工作区 + 共享包模式，既能支撑平台后台与低代码设计器的复杂交互，又能保障后续行业扩展和插件化演进，是适合快速开发平台的前端组织方式。
