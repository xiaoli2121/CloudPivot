# CloudPivot 低代码引擎设计

## 1. 设计目标

CloudPivot 低代码引擎的目标不是追求全无代码，而是面向技术团队与实施团队，提供“可配置 + 可扩展 + 可代码增强”的低代码能力，提升业务应用构建效率。

设计目标如下：

- 通过元数据驱动页面、表单和对象定义
- 打通设计态、发布态和运行态链路
- 支持基础组件编排、事件配置和运行渲染
- 允许在低代码能力之上进行代码扩展

## 2. 核心理念

- 元数据驱动：页面与对象能力通过结构化元数据描述
- 设计运行分离：设计态可频繁变更，运行态保持稳定加载
- 发布可追溯：每次发布形成版本快照，可回滚
- 配置优先、代码兜底：高频场景配置化，复杂场景支持二开

## 3. 引擎组成

低代码引擎由四部分组成：

### 3.1 元数据中心

负责：

- 业务对象定义
- 字段定义
- 页面定义
- 组件树配置
- 事件动作配置
- 发布版本管理

### 3.2 设计器

负责：

- 页面拖拽与布局配置
- 表单字段配置
- 属性面板编辑
- 事件与联动配置
- 草稿管理和发布入口

### 3.3 发布服务

负责：

- 设计稿合法性校验
- 草稿转发布版本
- 运行态快照生成
- 版本对比和回滚预留

### 3.4 运行引擎

负责：

- 加载元数据快照
- 渲染页面布局和组件
- 处理表单校验、动作执行、接口调用和生命周期

## 4. 元数据模型设计

### 4.1 对象模型

对象模型描述业务实体，例如：

- 对象编码
- 对象名称
- 存储策略
- 字段集合
- 主显示字段
- 状态字段

### 4.2 页面模型

页面模型描述运行界面，例如：

- 页面编码
- 页面类型
- 布局结构
- 区块配置
- 数据源绑定
- 操作区配置

### 4.3 组件模型

组件模型描述页面中的最小渲染单元，例如：

- 组件类型
- 属性配置
- 样式配置
- 校验规则
- 事件集合

### 4.4 动作模型

动作模型描述交互行为，例如：

- 提交表单
- 弹出对话框
- 刷新列表
- 跳转页面
- 调用接口

## 5. 设计态到运行态链路

1. 设计人员在 Designer Studio 中编辑页面和对象
2. 前端生成结构化设计数据
3. 后端设计器服务进行校验与保存
4. 发布时生成运行态快照
5. Runtime App 读取发布版本元数据进行渲染

设计态和运行态必须分离，避免草稿直接影响线上运行。

## 6. 运行引擎能力

运行引擎最小能力包括：

- 页面路由解析
- 元数据加载
- 组件树递归渲染
- 表单数据绑定
- 列表查询与分页
- 操作按钮与权限联动
- 基础动作执行

## 7. 数据源与查询设计

### 7.1 数据源分类

- 平台对象数据源
- 自定义接口数据源
- 字典和静态配置数据源

### 7.2 查询能力

- 列表查询
- 条件过滤
- 分页
- 排序
- 表单详情加载

数据源调用必须经过后端统一接口层，不能让前端直接拼接危险查询逻辑。

## 8. 组件物料体系

社区版 1.0 物料体系建议先覆盖高频组件：

- 页面容器
- 栅格布局
- 输入框、下拉框、日期、数字输入
- 表格
- 按钮
- 弹窗
- 描述信息

物料设计原则：

- 统一属性模型
- 统一事件模型
- 统一样式模型
- 统一注册机制

## 9. 规则与联动能力

社区版 1.0 优先支持轻量联动：

- 显隐控制
- 禁用控制
- 默认值计算
- 基础表单校验
- 组件间简单联动

复杂规则和跨页编排在后续版本增强。

## 10. 扩展机制

低代码引擎必须支持扩展：

- 新组件物料扩展
- 新动作类型扩展
- 新数据源适配扩展
- 新页面模板扩展

扩展必须通过插件体系和统一注册表完成，而不是直接修改引擎内核。

## 11. 社区版 1.0 落地范围

优先落地：

- 对象与字段元数据
- 页面与表单元数据
- 基础设计器骨架
- 基础运行时渲染
- 发布与版本快照基础机制

后续增强：

- 更复杂布局
- 流程编排与规则中心联动
- 图表大屏与门户设计
- 更强的模板市场能力

## 12. 设计结论

CloudPivot 低代码引擎以元数据驱动为核心，通过设计态、发布态和运行态分离实现稳定交付，既能覆盖社区版高频配置需求，也能为未来增强版能力扩展保留清晰演进路径。
