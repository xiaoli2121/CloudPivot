# CloudPivot 认证与权限设计

## 1. 设计目标

CloudPivot 认证与权限体系需要满足以下目标：

- 支持前后端分离场景下的统一登录与身份校验
- 支持菜单、按钮、接口和数据权限的统一授权
- 支持平台型项目常见的组织、角色、岗位和用户模型
- 保证社区版实现可落地，后续可平滑扩展

## 2. 总体方案

平台采用 Apache Shiro 作为认证与授权框架，在前后端分离场景下使用 Token 机制完成身份传递。

总体模式如下：

- 登录时校验账号密码，签发访问令牌
- 请求时通过 Shiro 自定义过滤器解析令牌并构建 Subject
- 授权时结合角色、资源权限和数据权限判断访问范围
- 登出或令牌失效时通过 Redis 状态控制实现快速失效

## 3. 认证模型

### 3.1 账号体系

社区版 1.0 支持以下基础账号属性：

- 登录账号
- 密码摘要
- 用户姓名
- 手机号
- 邮箱
- 所属组织
- 账号状态
- 超级管理员标识

### 3.2 认证方式

首期支持：

- 用户名 + 密码登录
- Token 鉴权
- 刷新令牌续期

预留扩展：

- 手机验证码登录
- 单点登录接入
- LDAP/AD 对接

### 3.3 令牌策略

- Access Token：短时有效，用于访问 API
- Refresh Token：较长有效期，用于续签 Access Token
- Redis：保存刷新状态、登出状态、黑名单或单端登录控制信息

## 4. Shiro 架构设计

### 4.1 核心组件

- `JwtToken`：封装访问令牌
- `JwtRealm`：完成身份校验与授权信息加载
- `JwtAuthFilter`：在请求入口解析令牌并构建登录上下文
- `SecuritySubject`：当前登录用户上下文对象

### 4.2 认证流程

1. 前端提交登录凭证
2. 后端认证服务校验账号状态、密码和登录策略
3. 认证成功后生成 Access Token 与 Refresh Token
4. 前端存储令牌并在后续请求中携带
5. 请求进入 Shiro 过滤器，解析令牌并完成身份确认
6. Realm 加载用户、角色、权限信息并写入授权缓存

### 4.3 登出流程

1. 前端调用登出接口
2. 后端将当前令牌加入失效控制集合或更新会话状态
3. 前端清理本地登录态

## 5. 授权模型

平台采用 RBAC 为主、数据权限为辅的授权模型。

### 5.1 角色授权

角色是授权的主要载体，角色与资源权限绑定，用户通过关联角色获得访问能力。

### 5.2 资源权限

资源类型分为：

- 菜单权限
- 按钮权限
- 接口权限
- 页面组件权限

资源权限码采用统一命名规则，例如：

- `system:user:view`
- `system:user:add`
- `system:user:edit`
- `system:user:delete`

### 5.3 数据权限

数据权限支持以下基础范围：

- 全部数据
- 本组织及下级
- 本组织
- 本人
- 自定义范围

数据权限由角色绑定策略，在查询层统一拼装条件。

## 6. 前端权限控制

前端负责体验层权限控制，不能替代后端授权校验。

前端控制维度：

- 动态菜单渲染
- 路由访问控制
- 按钮显隐
- 页面字段只读与可见性扩展

后端仍然必须做最终授权判断，避免前端绕过。

## 7. 后端权限控制

后端控制维度：

- 接口访问权限校验
- 业务操作权限校验
- 数据范围过滤
- 超级管理员特殊策略

建议通过统一注解、拦截器或服务层鉴权能力实现，避免权限判断分散在控制器和 SQL 中难以维护。

## 8. 缓存策略

缓存内容包括：

- 用户基础信息
- 用户角色集合
- 用户权限集合
- 数据权限策略

缓存原则：

- 登录后加载高频授权信息
- 用户、角色、菜单变更时主动失效缓存
- 避免缓存过深导致一致性问题

## 9. 安全策略

社区版 1.0 建议提供以下基础安全策略：

- 密码加盐摘要存储
- 登录失败次数限制
- 账号禁用与锁定机制
- 令牌过期与刷新控制
- 接口签名和时间戳校验预留
- 登录与关键操作审计日志

## 10. 社区版 1.0 落地范围

优先落地：

- 用户名密码登录
- Token 鉴权
- 菜单、按钮、接口权限控制
- 基础数据权限范围
- 登录日志与登出机制

后续增强：

- 更复杂的多终端登录控制
- 多因子认证
- 统一身份中心对接
- 更细粒度字段级权限

## 11. 设计结论

CloudPivot 认证与权限体系以 Shiro 为核心，以 RBAC 为基础模型，以数据权限为补充，通过统一的令牌机制和权限资源模型支撑平台管理与低代码运行场景，既满足社区版快速落地，又为增强版安全治理提供演进空间。
