# CloudPivot 产品定位

## 1. 产品愿景

CloudPivot 致力于打造一个企业级前后端分离开源快速开发平台，以低代码为能力中台，以标准化工程骨架、元数据驱动能力与插件化扩展机制为核心，帮助企业和交付团队快速搭建管理后台、业务应用和行业化解决方案。

平台强调三件事：

- 开箱即用：提供统一的管理后台、权限体系、组织模型、配置中心、低代码设计器和运行容器
- 低代码赋能：通过页面、模型、表单、流程、规则等元数据能力降低项目交付门槛
- 企业可扩展：支持前后端模块化、插件化和二次开发，满足行业项目长期演进诉求

## 2. 目标用户

### 2.1 直接用户

- 中小型软件公司和行业解决方案厂商
- 企业内部数字化平台团队
- 需要快速交付管理系统的实施与研发团队
- 希望在开源基础上形成私有化产品能力的技术团队

### 2.2 间接用户

- 业务管理员：通过后台完成用户、角色、菜单、参数和数据配置
- 业务设计人员：通过低代码设计器配置页面、表单和流程
- 最终业务用户：通过 PC 或移动端运行态应用完成业务操作

## 3. 核心价值主张

### 3.1 对研发团队的价值

- 降低项目初始搭建成本，减少重复造轮子
- 提供统一工程规范、模块边界和技术基线
- 通过低代码与代码生成结合，提高交付效率

### 3.2 对交付团队的价值

- 快速搭建行业项目的组织、权限、菜单和业务骨架
- 使用元数据驱动能力提升需求响应速度
- 通过插件机制封装行业能力，形成可复制交付模式

### 3.3 对企业客户的价值

- 获得可控、可私有化部署、可二开的平台底座
- 在统一权限、配置、审计和治理能力上扩展业务系统
- 降低长期运维和升级成本

## 4. 产品形态

CloudPivot 采用前后端分离架构，由三个主要工程组成：

- `cloudpivot-vue3`：PC 端前端工作台、设计器与运行容器
- `cloudpivot-springboot`：后端平台服务与低代码支撑能力
- `cloudpivot-uniapp`：移动端与小程序预留工程

平台初期采用模块化单体架构，优先保证开发效率、部署简单性和模块边界清晰；随着业务复杂度增长，再逐步演进为分布式形态。

## 5. 产品差异化定位

CloudPivot 不追求做“通用大而全”的低代码平台，而是聚焦“快速开发平台 + 轻量低代码底座 + 企业级治理能力”的平衡路线。

差异化重点如下：

- 不是纯脚手架：不仅有基础 CRUD，还包含权限、元数据、插件与设计态能力
- 不是纯无代码：保留代码扩展能力，面向技术团队而不是完全零门槛用户
- 不是过度复杂的平台中台：社区版优先交付稳定底座与高频能力，避免一开始引入过多重量级组件

## 6. 社区版 1.0 产品边界

社区版 1.0 聚焦“可运行、可扩展、可二开”的基础底座，优先完成以下能力：

- 用户认证、角色授权、菜单与按钮权限
- 组织、岗位、用户、字典、参数等基础平台能力
- 元数据模型、页面定义和基础运行容器
- 设计器基础骨架与插件扩展基础能力
- 标准前端工作台与后端管理 API

社区版 1.0 暂不以复杂工作流编排、复杂规则引擎、分布式微服务治理、多租户高级运营能力为首要交付目标，这些能力以预留模块和后续路线图形式规划。

## 7. 核心业务场景

### 7.1 平台初始化场景

管理员初始化组织、角色、用户、菜单、字典、参数和资源权限，形成统一平台底座。

### 7.2 快速业务构建场景

研发或实施人员通过元数据配置基础业务对象、页面布局、表单字段和列表视图，快速生成应用骨架。

### 7.3 行业能力沉淀场景

团队通过插件、模板、组件和业务模块封装行业经验，在后续项目中复用。

### 7.4 私有化交付场景

客户在私有环境部署平台，通过二次开发和配置方式持续扩展业务系统。

## 8. 版本策略

### 8.1 社区版

- 提供快速开发平台底座与基础低代码能力
- 强调开源、可学习、可扩展、可二开
- 适合技术团队建立内部平台能力

### 8.2 增强版或企业版方向

- 面向复杂组织、多租户、流程集成、审计合规和运营能力强化
- 增加更完善的插件市场、应用市场、数据治理和运维治理能力
- 建立标准化升级与商业支持体系

## 9. 成功标准

CloudPivot 社区版 1.0 的成功标准包括：

- 能在单机环境下快速启动前后端工程
- 能完成统一登录、权限控制和基础后台管理
- 能基于元数据构建基础页面与运行态展示
- 能支持团队在该底座上进行稳定二次开发
- 能沉淀为后续增强版演进的统一技术与产品基线
