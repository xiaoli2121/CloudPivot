# CloudPivot 社区版 1.0 实施计划

## 1. 计划目标

社区版 1.0 的目标是交付一个可运行、可扩展、可二次开发的企业级前后端分离快速开发平台基础底座，完成平台管理和基础低代码的主链路闭环。

## 2. 实施范围

社区版 1.0 聚焦以下范围：

- 前端基础管理台
- 后端模块化单体骨架
- 基础认证与权限
- 组织、用户、角色、菜单等平台能力
- 字典、参数、日志等系统基础能力
- 元数据中心与设计器骨架
- 基础运行态容器
- 插件机制基础设施

## 3. 分阶段实施

### 第一阶段：工程基础搭建

目标：

- 建立前端多应用工作区
- 建立后端模块化单体工程
- 打通基础启动、联调和健康检查链路

交付物：

- 前端工程骨架
- 后端工程骨架
- 基础启动脚本
- 基础文档

### 第二阶段：平台基础能力建设

目标：

- 完成统一登录与认证授权
- 完成用户、角色、菜单、组织等基础能力
- 完成参数、字典、日志等系统功能

交付物：

- 登录与权限主链路
- 平台基础管理页面和 API
- 标准响应与异常体系

### 第三阶段：低代码基础能力建设

目标：

- 完成元数据中心基础能力
- 完成设计器基础骨架
- 完成运行态基础渲染闭环

交付物：

- 元数据对象和页面模型
- 页面设计与发布基础流程
- 运行容器基础能力

### 第四阶段：扩展能力与收尾

目标：

- 完成插件基础机制
- 完成示例、文档和版本整理

交付物：

- 插件注册机制
- 示例扩展点
- 发布说明与部署说明

## 4. 优先级划分

### P0 必做

- 前后端可启动
- 统一登录
- 角色菜单权限
- 用户组织管理
- 系统字典参数
- 元数据中心基础模型

### P1 应做

- 设计器基础骨架
- 运行态页面渲染骨架
- 插件基础机制

### P2 预留

- 工作流增强
- 规则引擎增强
- 集成连接器增强
- 多租户增强

## 5. 实施建议节奏

建议按以下顺序推进：

1. 先完成后端基础底座与认证权限
2. 再完成前端管理台主入口与基础管理页面
3. 再补元数据与设计器、运行态闭环
4. 最后整理插件机制和发布资产

## 6. 质量要求

- 每个模块必须具备明确职责
- 核心主链路必须可联调
- 关键接口具备基础测试
- 文档与工程结构保持一致
- 不在社区版 1.0 阶段引入不必要复杂度

## 7. 风险控制

### 7.1 范围膨胀

控制方式：

- 坚持 P0/P1/P2 分层，不将预留能力挤进 P0

### 7.2 架构先行过度

控制方式：

- 先做可运行骨架，再做高级抽象

### 7.3 低代码闭环不完整

控制方式：

- 必须确保“设计保存 - 发布 - 运行渲染”最小链路成立

## 8. 验收标准

社区版 1.0 验收至少满足：

- 前端工程可启动并访问后台入口
- 后端工程可启动并提供标准健康检查
- 登录认证与基础权限可用
- 用户、角色、菜单、组织管理基础能力可演示
- 元数据基础能力和运行容器具备最小演示闭环
- 文档完整，结构清晰，可支持后续二次开发

## 9. 计划结论

CloudPivot 社区版 1.0 的实施计划应坚持“先底座、后增强，先主链路、后高级能力”的思路。只要按阶段稳定推进，就能较快形成一套具备开源价值和落地价值的平台基础版本。
